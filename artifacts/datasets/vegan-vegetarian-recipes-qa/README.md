# Vegetarian & Vegan Recipe Q&A

A synthetic instruction-tuning dataset of **11,582** recipe Q&A pairs, about 61% vegetarian and 39% vegan, generated by a 32B teacher model from permissively-licensed cookbook sources. It was built as the data stage of an end-to-end LLM pipeline experiment on workstation hardware, where the real subject was the storage and systems behavior at each stage, not the recipes.

> **Companion materials:** the [Qwen3-8B LoRA model](https://huggingface.co/knachiketa004/vegetarian-recipe-qwen3-8b-lora) trained on this set, and the methodology article *[What I learned building an LLM pipeline on a workstation](https://github.com/knachiketa04/aihomelab/tree/main/artifacts/concepts/llm-pipeline-on-a-workstation)*.

## The honest summary first

This is synthetic, narrow (recipes only), and its dietary correctness is good but not perfect. It is a solid base for instruction-tuning a recipe model or for studying teacher-student distillation. It is not a curated, human-verified gold set. Read the Dietary correctness and Known limitations sections before you rely on it, especially the part about why a keyword screen is not enough.

## What's in this dataset

Each row is a single instruction-response pair: a recipe-related question and a coherent answer that provides a recipe, suggests a substitution, adapts a dish to a dietary constraint, explains a technique, or recommends a meal for a nutrition target.

**Dietary split** (the strict definitions):

- **vegetarian** (7,016 rows, ~61%): dairy and eggs permitted; no meat, fish, or seafood
- **vegan** (4,566 rows, ~39%): no animal products

**Templates (10).** Six general templates carry the bulk of the data, plus four India-specific templates for sub-regional coverage:

| Template | What it asks | Rows | Approx % |
| --- | --- | --- | --- |
| `constraint_cooking` | recipe from a specific ingredient list | 1,889 | ~16% |
| `substitution` | ingredient substitution in a dish | 1,852 | ~16% |
| `adaptation` | adapt a source recipe to vegan/vegetarian | 1,828 | ~16% |
| `nutrition_target` | nutrition-anchored meal recommendation | 1,805 | ~16% |
| `technique_explainer` | what a cooking technique is and when to use it | 1,805 | ~16% |
| `cross_cuisine` | how a chef from cuisine A adapts dish B | 1,804 | ~16% |
| `indian_regional_dal` | regional Indian dal | 167 | ~1% |
| `indian_south_breakfast` | South Indian breakfast | 160 | ~1% |
| `indian_paneer_ghee_substitution` | vegan swaps for paneer/ghee | 136 | ~1% |
| `indian_sweet_adaptation` | adapting Indian sweets | 136 | ~1% |

**Cuisines.** 30 distinct cuisine labels, present on about **36% of rows** (4,208 of 11,582); the rest carry no cuisine tag. The labeled subset has intentionally strong representation of Indian sub-regional cuisines (Indian, Gujarati, Bengali, Kashmiri, Maharashtrian, and more) alongside Western, East Asian, Middle Eastern, and Southeast Asian traditions.

## Dataset structure

Splits are `train` / `validation` / `test`. Each row is a self-contained JSONL record:

```json
{
  "messages": [
    {"role": "user", "content": "What vegan dish can I make with..."},
    {"role": "assistant", "content": "You can make a quick and flavorful..."}
  ],
  "template": "constraint_cooking",
  "dietary_preference": "vegan",
  "cuisine": "Hyderabadi",
  "grounding_row_id": 4821
}
```

- `messages`: chat-messages format, compatible with TRL, Axolotl, and most fine-tuning toolchains.
- `template`, `dietary_preference`: provenance and stratification keys.
- `cuisine`: the cuisine label, or absent/null for the ~64% of rows generated without a cuisine anchor.
- `grounding_row_id`: on the subset of rows whose prompt was anchored to a public-domain source recipe, an integer pointer into the grounding corpus (in the reproduce kit). Useful as provenance; ignore it if you do not need it.

## Splits and a known overlap

| Split | Rows |
| --- | --- |
| train | 10,424 |
| validation | 579 |
| test | 579 |

These are a **row-level random split**. One honest caveat: because the prompts are templated, the same prompt string recurs across splits. About **35% of test prompts also appear in train**, each with a different generated answer. There are **zero duplicate rows** (no prompt-and-answer pair appears in more than one split). For training this is irrelevant. For a strict held-out evaluation, **deduplicate by prompt** first, or carve your own split. The companion model was trained on this `train` split as-is.

## How this dataset was generated

1. **Corpus assembly.** Three sources were ingested and cleaned: Wikibooks Cookbook (CC BY-SA 3.0), Project Gutenberg cookbooks (public domain), and Wikipedia food articles (CC BY-SA 4.0). Schema unification, vegan/vegetarian classification by ingredient inspection, and MinHash deduplication produced a vegan-and-vegetarian recipe set used as format-shape few-shot examples plus an all-source set used as grounding context.
2. **Prompt construction.** The ten templates were filled across dietary preference, cuisine, ingredient lists, nutrition targets, and excerpts from the grounding corpus (referenced per row by `grounding_row_id`), with a fixed shared prefix (system message plus few-shot examples) and a request-specific user prompt.
3. **Teacher generation.** `Qwen/Qwen3-32B` at FP16 (~61 GiB) served via vLLM 0.21 with prefix caching, temperature 0.7, top_p 0.95, thinking mode disabled in the chat template.
4. **Data-parallel execution** across two NVIDIA DGX Spark workstations, with a chunked-restart orchestration to manage UMA allocator pressure (see the methodology article for the specific failure mode this works around).
5. **Validation.** Output was checked for thinking-mode leak (measured at roughly 0.05%, effectively zero), truncation (none observed), and template balance. **12,368** successful generations were processed into the **11,582** released rows after parsing, formatting, and deduplication.

## Dietary correctness, honestly

This is the part to read. A cheap keyword screen looks for animal-product terms inside vegan or vegetarian recipes. About **14% of rows trip that screen**, but inspection shows the screen **massively over-flags**: the large majority are `adaptation` and `substitution` recipes that name the ingredient precisely in order to remove or replace it. Real examples that the screen flags as violations:

- *"Omit the meat and stockfish"* (flagged for "stockfish")
- *"use vegetable-based alternatives like king oyster mushrooms"* (flagged for "oyster")
- *"replace the eggs with a flaxseed 'egg'"* (flagged for "egg")
- *"What can I substitute for ricotta when making vegan biryani?"* (flagged for "ricotta")

None of those are violations; they are correct substitutions, which is exactly why a keyword filter is not enough and a real check needs an LLM judge (the central lesson of the companion article's eval stage). **This dataset keeps the flagged rows**, because substitution and adaptation examples are a core part of the dataset's purpose. A residual minority of flagged rows are likely genuine slips (a "vegan" recipe that actually uses a dairy ingredient). For any use where dietary correctness matters, run a second-pass **LLM-judge** filter, not a keyword screen.

## Known limitations

- **Single-language.** All Q&A is in English.
- **Domain-narrow.** Recipes only. Strong for recipe Q&A, weak for general instruction tuning.
- **Residual dietary errors.** As above, a minority of rows may contain a genuine dietary slip. Judge before strict use.
- **Cuisine attribution imprecision.** Regional labels (Bengali, Kashmiri, and so on) are sometimes wrong even when the dish is described correctly.
- **Technique depth varies.** Some `technique_explainer` rows are detailed, others surface-level.
- **No standardization** of cooking times or serving sizes across answers.
- **Split overlap.** See Splits above: templated prompts recur across splits (no duplicate rows). Dedup by prompt for strict held-out eval.

## Reproducibility

Built as the data stage of an end-to-end LLM pipeline experiment in the AIHomeLab project, a personal-capacity AI infrastructure storage lab on two NVIDIA DGX Spark workstations.

- **Companion model**: [knachiketa004/vegetarian-recipe-qwen3-8b-lora](https://huggingface.co/knachiketa004/vegetarian-recipe-qwen3-8b-lora)
- **Methodology article**: *What I learned building an LLM pipeline on a workstation*
- **Source code**: generation scripts, templates, prompt builder, and the corpus-cleaning pipeline in the [AIHomeLab repository](https://github.com/knachiketa04/aihomelab)

Reproducing the full generation takes roughly 11 hours on similar hardware (2x DGX Spark). A shared parallel filesystem is not required; local NVMe is sufficient at this size.
